# 从参考模型到 F2：每一步做了什么、为什么这样选

这份文档按时间顺序记录方法是怎样一步步优化到 F2（Codabench val Δm **44.84**）的：每一步试了什么、结果如何、为什么采用或放弃，以及每个部分的取舍。实验在 2026-10-20 到 10-23 之间完成，共 67 次训练、约 155 GPU 小时，硬件是 2 × RTX 6000 Ada。

## 1. 出发点：任务、指标和约束

**指标**：Δm 是 macro-F1 和 mAP 相对参考模型的变化率的平均：

Δm = ½ × [(F1 − F1_ref) / F1_ref + (mAP − mAP_ref) / mAP_ref] × 100

Codabench val 的参考值是 F1 93.31 / mAP 26.13。参考 mAP 很低，所以 mAP 每涨 1 个点，Δm 涨约 1.9；F1 每涨 1 个点，Δm 只涨约 0.54，前者约是后者的 3.6 倍。分类已经在 93–96 之间接近饱和，**所以整个优化的重心是检测 mAP**。

**数据**：
- 9 个类别，9,392 张有标注的 SAR 图像。
- 70% 的框属于 COCO 定义的小目标。按 512 输入算，一半的框边长不到 16 像素，也就是小于一个 ViT patch。
- 风机、桥梁、油罐的中位边长只有 8–12 像素。
- 桥梁和操场的 AP 一开始几乎为 0。看了图像，标注没有错，是这两类本身就难：桥梁是河流和道路交叉处 6–10 像素的小点，操场是密集城区里约 15 像素的小块。

**规则约束**（Codabench Terms），决定了哪些路能走：
- 总参数 ≤130M，可训练参数 ≤40M（含检测头）。
- 单模型，不能集成，不能 TTA。
- 每张图只输入一次，分辨率 ≤512，不能切块。
- 不能用其他 SAR 数据或 SAR 预训练模型，不能在 val / test 图像上训练。

## 2. 评估方法：怎样判断一个改动有没有用

- **本地划分**：从有标注数据里按固定种子切出 train 7,512 / val 940 / test 940 张。
- **本地基准**：本地划分和官方不同，训练数据也只有 80%，所以先在本地复现参考模型（E00），本地 Δm 以它为基准。不能直接用官方参考值算。
- **采用标准**：两个本地留出集（val 和 test）都要提升，平均 mAP 至少 +0.4。只看一个集合很容易被噪声骗。
- **噪声估计**：后来用 36 个不同种子重复 C36 配方，测出单次运行的噪声约为 ±0.35 mAP。
- **校准**：本地分数会高估 Codabench。V2 在本地估计约 +44.8，在 Codabench 上是 38.23。原因有两个：本地有近似重复图；两边的类别比例也不同，Codabench val 里风机和机场更多，桥和港口更少。所以**本地分数只用来比较方案的高低，绝对水平以 Codabench 为准**。
- **防止对本地数据调参**：
  - 超参数只在很少的几个整数或粗粒度值里选，例如 λ ∈ {0, 0.5, 1}。
  - 后处理的设置要在 3 个模型 × 2 个留出集上方向一致才采用。

## 4. 每个阶段的细节和取舍

### 阶段 1：选骨干

**试了什么**：
- DINOv3 ViT-B/16（E01）
- DINOv3 ConvNeXt-T 全量微调（E07）
- 计划过 DINOv3 ConvNeXt-B（E03）和 DINOv2 ViT-B/14

**结果**：只换骨干，DINOv3 ViT-B/16 就带来 +8.1 Δm（加上后处理是 +10.9），当时是最大的单项提升。

**取舍**：
- **DINOv3 ViT 和 ConvNeXt-T 全量微调**：
  - ConvNeXt-T 加检测头一共只有 35.5M 参数，可以在 40M 的可训练上限内全部训练。参考代码里全量微调比 LoRA 高约 13.5 Δm，所以这条路看起来很有吸引力。
  - 实测只有 +6.8。ConvNeXt 虽然有步长 4 的高分辨率特征，小于 8 像素的目标 AP 只有 1.9，比参考模型还低。
  - 结论是 DINOv3 在小目标上弱，是它的预训练本身造成的，和用 ViT 还是 ConvNeXt 无关。
  - 选 ViT-B：总参数 86M 的大模型冻结、只训练 LoRA，比 35M 的小模型全量微调更好。
- **DINOv2 ViT-B/14**：patch 14 在 512 输入下无法整除，特征网格和锚框会错位，所以没有用。
- **代价**：DINOv3 在 16 像素以上的目标上明显更强，但在 16 像素以下比 IN21k 更差。后面的检测头和 A4 主要就是在补这个短板。

### 阶段 2：适配方式（LoRA 加在哪、多宽）

**试了什么**：
- E02：IN21k，LoRA 从只加在注意力层扩到所有线性层（qkv / proj / fc1 / fc2），秩 32，同时训练 LayerNorm，LoRA 学习率 3e-4。
- E09b：按调研建议的“宽 LoRA”，DINOv3 + 秩 64 + LoRA+ ×2 + drop path 0.1，偏置和 layer scale 也训练。
- E04r：DINOv3 + E02 原样的配方。
- D6：E04r 的秩改为 64。

**结果**：
- 只扩大适配容量（E02，+11.4）比只换骨干（E01，+8.1）收益更大。
- E09b 分类最好（F1 95.2），但检测反而比 E01 还差。
- 诊断实验 E04r 证明问题出在 E09b 额外加的那些设置（drop path、LoRA+、更强的正则），而不是 DINOv3 本身。E04r 得到 +18.1，两个留出集一致，成为后面所有实验的基础。

**取舍**：
- **秩 32 还是 64**：r64 只多 +0.6，在噪声范围内，还要多占 4.7M 可训练参数。选 r32，把预算留给检测头。
- **训练 LayerNorm**：参数很少，但能让特征分布适应 SAR 图像，一直保留。
- **不训练 patch embedding**：后来的 S6 实验以小学习率训练它，只有很小的收益，不采用。

### 阶段 3：检测头和小目标

每次只在 E04r 上改一项，24 轮。

**有效的两项**：
- **Cascade R-CNN（D1）**：3 个阶段（IoU 0.5 / 0.6 / 0.7），用轻量的类无关框头，RoIAlign 对齐到像素中心。
  - mAP 在 val / test 上 +1.39 / +1.23。在 IN21k 上的对照实验 V1 也有 +1.6，两种骨干上都有效。
  - 动机：AP50 和 AP75 差距很大，飞机 71 对 16，风机 46 对 4。一个 8 像素的风机要达到 IoU 0.75，定位需要精确到约 1 像素，所以瓶颈是定位精度。
  - 代价：可训练参数反而少了约 1M（23.8M 对 24.9M），因为框头是轻量的。
- **NWD 匹配和小锚框（D2）**：
  - RPN 按 max(IoU, NWD) 匹配，C = 8。最小锚框 6 像素，锚框中心对齐像素。
  - 原因：一个 8 像素的框偏几个像素，IoU 就几乎为 0，正样本会被丢掉。NWD 把框看成高斯分布来算距离，对小框的偏移宽容得多。
  - 结果 Δm +1.6（mAP +0.88 / +0.57），采用。

**放弃的几项**：
- **CNN 空间先验 + 多层特征颈部（D3）**：24 轮下大幅变差。后来查明主要是多层颈部的问题：它让最高分辨率的特征来自浅层 block，语义太弱。
  - 只加空间先验（S5）在 36 轮下是 +0.8 / +0.9。这个结果出来时 F2 已经开训，所以没进 F2，是下一版的首选。
- **D4 旋转翻转 + 同类复制粘贴（D4）**：大幅变差。在 100 轮长训练里又测了一次（L1），也没用。
- **Mona 适配器（D5）**：启动时 cuDNN 报错，当时有更有把握的方向，就没有再修。

### 阶段 4：训练长度（单项最大的提升）

**结果**：
- 同一配方从 24 轮延长到 36 轮（L36），本地 Δm 从 +18.1 升到 +29.4。
- 加上 Cascade + NWD 后，36 轮（C36）是 +31.3，48 轮（C48）是 +38.6。

**V2 实验**：两卡 DDP，余弦学习率 120 轮。在本地 train + val 上训练，留本地 test 作监控，每 10 轮评估一次。用最终后处理，各轮的本地 test mAP 是：

| 轮数 | 70 | 80 | 90 | 100 | 110 | 120 |
|---|---|---|---|---|---|---|
| mAP | 46.92 | 47.84 | 48.31 | **48.91** | 48.61 | 48.54 |

第 90 轮以后进入平台期，没有明显过拟合。

**取舍**：
- **选 100 轮**：100 到 120 轮之间只差约 0.4，在 940 张集合的噪声范围内，100 轮更省时间。
- **用余弦降到 0**：学习率降到 0 时模型本身就被平滑了。EMA 实验（E1）证实这一点：加了 EMA 基本打平（+0.18 / −0.30），所以不用 EMA。
- **两卡 DDP**：保持全局 batch 16 不变，速度从每秒 37 张提到 72 张。这一步让 100 轮的训练从 7 小时缩短到 3.6 小时，后面的全量训练才来得及做。

### 阶段 5：后处理

这些都只作用于同一次前向传播的输出，不是集成或 TTA，符合规则。每一项都要求在多个模型、两个留出集上方向一致才采用。

| 步骤 | 本地效果 | 说明 |
|---|---|---|
| 检测辅助分类：argmax(log p_分类 + λ·log 该类最高检测概率)，λ = 1 | 弱模型 F1 +1；强模型 ±0.2 | λ 只在 {0, 0.5, 1} 里选，三个模型上差别在噪声内，保留 1 |
| 框分数 × RPN 物体性^0.25 + 按类 Gaussian soft-NMS（σ 0.75） | +1.3 ~ +1.8 mAP | σ 取 0.5–1、指数取 0.25–0.5 结果差不多，不是调出来的 |
| 三个 Cascade 阶段的框取平均 | +0.3 ~ +0.5 mAP | 和 Cascade 对分类概率取平均的做法一致；试过加权，差别 ≤0.06，用等权 |
| 所有框平移 −0.4 像素 | +0.4 ~ +0.7 mAP | 发现标注有系统偏差，见阶段 7 的 A2 |
| 分数阈值 1e-5，每张图至少 30 个框 | +0.06 ~ +0.16 mAP | 原来有 84 张 val 图一个框都没有；COCO AP 在排序末尾补低分框只增加召回，不降低精度 |

**反例**：
- 用图像分类概率给检测框重新打分，基本无变化。说明检测错误主要是定位不准，不是类别混淆。
- IoU 质量分支（B1）用预测的 IoU 重新打分，越用越差，强度 1 时 Δm −1.1，放弃。

### 阶段 6：全量数据（F1）

**做法**：V2 的配方，但用全部 9,392 张有标注图训练 100 轮，不留任何本地留出集。

**结果**：Codabench val 41.26，比 V2 第 100 轮（38.23）高 3.03。mAP +1.35，F1 +0.84。

**取舍**：
- 用全部数据，就没有留出集可以监控或挑检查点。
- 这样做可行，是因为 V2 已经证明 100 轮是平台期、不会过拟合，所以直接取最后一轮。
- 多 940 张数据（+11%）的收益，比保留监控能力更重要。

### 阶段 7：精修，F1 → F2

改动都在 36 轮的 C36 配方上筛选，对比同一套最终后处理下的 C36（本地 val / test mAP 37.22 / 39.04）。

**A4：Cascade IoU 阈值随目标尺寸变化**（`--cascade-size-iou`）
- 默认的 0.5 / 0.6 / 0.7 阈值下，小目标在第 2、3 阶段几乎没有正样本。A4 对小目标放宽阈值：

| 目标边长 | 三个阶段的 IoU 阈值 |
|---|---|
| < 8 像素 | 0.40 / 0.45 / 0.50 |
| 8–16 像素 | 0.45 / 0.50 / 0.55 |
| 16–32 像素 | 0.50 / 0.55 / 0.65 |
| 更大 | 0.5 / 0.6 / 0.7（不变） |

- 结果 mAP +0.93 / +0.74。按尺寸看：

| 目标边长 | <8 | 8–16 | 16–32 | 32–96 | ≥96 |
|---|---|---|---|---|---|
| C36 的 AP | 8.2 | 17.0 | 28.4 | 52.4 | 47.6 |
| A4 的 AP | 12.9 | 20.7 | 28.2 | 50.4 | 47.6 |

- **取舍**：小目标大涨，32–96 像素掉了 2 个点。为了保住中等目标，试了 A4b：只对 16 像素以下放宽，16 像素以上保持默认。
  - A4b 的 32–96 像素照样掉了 2.6，总分反而比 A4 低约 0.35。
  - 说明中等目标的损失不是它们自己的阈值造成的，而是小目标新增的低 IoU 正样本影响了共享的分类头。
  - 这个代价换来的净收益仍然最大，保留 A4。

**A2：翻转偏差修正**（`--flip-bias -0.3`）
- **发现**：把预测框整体平移 −0.4 像素（以 512 输入为准），3 个模型、2 个留出集上 mAP 都稳定提高。
- **排除其他解释**：分开平移左上 / 右下角、分开平移 x / y、按原图尺寸换算，最优都还是统一 −0.4，其他方案差别不超过 ±0.02。折合到原图约 −0.3 像素，在 512 和 256 两种原图尺寸上一致。所以这最可能是标注坐标约定造成的系统偏差。
- **推论**：翻转增强会把这个偏差变成相反方向，同一个目标的回归目标在 ±0.3 像素之间来回摆动。这对小于 8 像素的目标影响不小。
- **做法**：翻转时把框额外挪动两倍的偏差，让所有训练目标保持同一种坐标约定。
- **结果**：mAP +0.64 / +0.57，而且不再需要 −0.4 的平移，这也验证了上面的解释。
- **残余平移**：A2 训练出的模型再加 −0.2 像素平移，val / test 各多 +0.2 mAP；+0.2 方向则不好。所以 F2 用 −0.2。

**A4 + A2 能不能叠加（AA）**
- 两项一起开，相比 36 个种子的 C36 均值（37.46±0.35 / 38.90±0.37），是 38.43 / 40.01，约 +1.0 / +1.1。
- 能叠加，但比两项单独收益之和小。

**F2 的 Codabench 结果**：

| | Δm | macro-F1 | mAP | AP50 |
|---|---|---|---|---|
| F1 | 41.26 | 95.90 | 46.97 | 71.57 |
| F2（shift −0.2） | **44.84** | 95.46 | **48.97** | 71.53 |

- mAP +2.00，比本地 36 轮实验估计的 +1.0 还大，可能是因为 Codabench val 的小目标类别（风机）更多。
- F1 −0.44，只损失约 0.24 Δm。
- AP50 不变，提升全部来自更高 IoU 阈值下的定位精度，正好是 A4 和 A2 针对的问题。

## 6. 贯穿始终的几个原则

1. **先看指标结构再定方向**。mAP 对 Δm 的影响是 F1 的 3.6 倍，所以绝大多数 GPU 时间花在检测上。
2. **每次只改一项，在当前最好的配方上做**。E09b 把多项设置混在一起，检测变差后又花了一次诊断实验（E04r）才找出原因，之后都严格单项筛选。
3. **看分解结果，不只看总分**。按尺寸、按类别看 AP，才发现 DINOv3 在小目标上弱、定位精度是瓶颈、A4 有中等目标的代价。
4. **规则优先**。所有后处理都只作用于同一次前向传播；最终模型可训练参数 23.8M、总参数 109.0M，离 40M / 130M 上限都留了余量。
5. **两个留出集都要提升，再用 Codabench 校准**。每一项被采用的改动，最后在 Codabench 上也确实带来了提升：V2 38.23 → F1 41.26 → F2 44.84。
